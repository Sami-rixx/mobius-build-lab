# Contributing to MÖBIUS Build Lab

Thank you for your interest in contributing to MÖBIUS Build Lab. This document outlines how we collaborate, what we expect from contributors, and how you can participate effectively.

## Our Collaboration Workflow

The Build Lab uses a simple, structured workflow designed for clarity and learning:

```
Assign Issue → Understand → Research → Build/Document/Test → Record Activity → Pull Request → Review → Merge
```

### 1. Assign Issue

- All work starts with a GitHub Issue
- Browse open Issues and express interest by commenting
- **Do not begin work until the Issue is assigned to you**
- If you have a new idea, create an Issue for discussion before starting

### 2. Understand

- Read the Issue thoroughly
- Review linked documentation, decisions, and discussions
- Clarify any ambiguities by asking questions in the Issue thread
- Understand the "why" behind the task, not just the "what"

### 3. Research

- Investigate existing code, documentation, and external references
- Document findings that inform the solution
- Identify constraints, dependencies, and risks
- For significant tasks, create a brief research summary before implementation

### 4. Build/Document/Test

- Create a branch: `git checkout -b username/issue-short-description`
- Implement the solution or create the documentation
- Write tests where applicable
- Update relevant documentation
- Validate your work locally before submitting

### 5. Record Important Activity

- Update your collaborator profile with significant work
- Document AI-assisted activity if material to the outcome
- Note important decisions made during implementation
- Record outputs and files produced

See [AI-COLLABORATION.md](./AI-COLLABORATION.md) for guidelines on documenting AI-assisted work.

### 6. Pull Request

- Submit a Pull Request from your branch to `main`
- Reference the Issue in the PR description
- Complete the PR template honestly and thoroughly
- Keep PRs focused and reviewable (smaller is better)

### 7. Review

- All PRs require at least one approval from a maintainer
- Address all review feedback promptly
- Update the PR description if the scope changes significantly
- Be responsive to questions and requests for clarification

### 8. Merge

- Only maintainers merge PRs into `main`
- PRs are merged when all discussions are resolved and required approvals are obtained
- The assigned maintainer merges after final approval

## Expectations

### For All Contributors

- **Be transparent:** Document your work and reasoning
- **Be responsible:** Validate and understand what you submit
- **Be collaborative:** Help others and ask for help when needed
- **Be patient:** Learning takes time; quality takes priority over speed

### For Human Contributors

- You are responsible for understanding, reviewing, testing, and validating any AI-assisted work you submit
- Do not blindly trust AI-generated code, documentation, or decisions
- If you used AI significantly, document it according to [AI-COLLABORATION.md](./AI-COLLABORATION.md)

### For AI Coding Agents

- Follow the workflow above
- Create branches for changes
- Submit PRs for review
- Document your activities and the human decisions that guided your work
- Leave a lightweight, human-readable footprint of significant AI-assisted work

## Getting Started

1. **Familiarize yourself** with the repository structure and existing documentation
2. **Read** [GOVERNANCE.md](./GOVERNANCE.md) to understand project leadership
3. **Read** [AI-COLLABORATION.md](./AI-COLLABORATION.md) to understand AI guidelines
4. **Find an Issue** that interests you and is marked as available
5. **Comment** on the Issue expressing your interest
6. **Wait for assignment** before beginning work

## Code of Conduct

By participating in MÖBIUS Build Lab, you agree to:

- Treat all contributors with respect and courtesy
- Communicate openly and honestly
- Give and receive constructive feedback
- Take responsibility for your contributions
- Respect that participation does not grant equity, ownership, or revenue rights
