# MÖBIUS Build Lab

**MÖBIUS Build Lab** is a mentor-led community initiative where people learn how to build real products with AI. This repository serves as the central workspace, institutional memory, and development environment for all Build Lab activities.

## Purpose

This repository exists to:

- Provide a structured, transparent environment for collaborative product development
- Serve as the authoritative source for project documentation, decisions, and progress
- Enable both human contributors and AI coding agents to work safely and effectively
- Maintain a clear record of all work for learning, review, and future reference

## Project #001: Attention Mirror

**Attention Mirror** is the first project undertaking of MÖBIUS Build Lab. It is a WhatsApp-based attention accountability product currently in the **early discovery and pre-development stage**.

> **Status:** Discovery Phase - Requirements gathering, research, and architectural exploration in progress.

Project documentation is organized under [`docs/projects/attention-mirror/`](./docs/projects/attention-mirror/).

## How Collaborators Work

The Build Lab follows a structured, transparent workflow:

1. **Issues First:** All work originates from GitHub Issues
2. **Branches for Changes:** Contributors work in feature/topic branches
3. **Pull Requests for Review:** All changes are reviewed before merging
4. **Documentation First:** Significant decisions and research are documented before implementation
5. **AI as Partner:** AI agents assist but human understanding and validation is required

See [CONTRIBUTING.md](./CONTRIBUTING.md) for the detailed workflow.

1. Read [CONTRIBUTING.md](./CONTRIBUTING.md) to understand the workflow

3. Explore open Issues and Pull Requests
4. Introduce yourself and express interest in a specific Issue
5. Wait for assignment before beginning work

## Principles

- **Transparency:** All significant work is visible and documented
- **Accountability:** Contributors are responsible for their work and AI-assisted outputs
- **Learning:** The primary goal is building real skills, not just shipping code
- **Quality:** Working software and clear documentation over speculative features
